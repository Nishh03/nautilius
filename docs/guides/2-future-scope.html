01 Where it stands today

The foundations are done, and they are the part that is hard to retrofit.

Nautilus reads a folder of notes, answers questions from them with cited sources, draws a study plan that grades itself, and runs seven agents that maintain the vault on a schedule. It uses four AI providers interchangeably and costs nothing to run.

That matters for what comes next, because the expensive part of a system like this is not the interface — it is the layer underneath that actually coordinates work. Adding features now is mostly writing new agents against an existing contract, which is cheap. The order was right.

The design decision everything else rests on

The vault is shared memory. Agents read it, write to it, and read each other's output. There is no message bus, no job queue, and no database — a markdown folder does the coordinating. That is why a new agent costs an afternoon instead of a week.

02 Three horizons

Next — weeks

Make it sharper

Better retrieval, measurable answer quality, and a progress chart with real history behind it. Nothing new to learn, everything already scaffolded.

Then — months

More agents

Agents that teach, rehearse, and plan rather than only organise. The registry already supports them; each is a script and a row.

Later — a year

A platform

Multiple people, shared vaults, mobile capture, and a way for anyone to write their own agent without touching the core.

03 Next — make what exists sharper

Each of these improves something already working, and can be built without changing the architecture.

Semantic search

Today a note about “cars” is invisible to a question about “automobiles”. Embeddings would fix that. The honest test is whether it beats keyword scoring on a fixed question set — if not, it does not earn the dependency.

Mediumretrieve.py only

An answer quality score

A fixed set of questions with known-good sources, run on every change, so retrieval quality becomes a number that can go up or down instead of a feeling.

Streaming answers

The answer currently arrives complete and is revealed. Real token streaming would make it appear as the model writes it — the difference between waiting six seconds and watching for six seconds.

Easybackend + frontend

A real progress chart

The Progress agent already records a dated snapshot each day. After a few weeks there is a genuine growth curve to draw — notes written, topics cleared, gaps closing.

Right now Nautilus reads and agents write. Letting a person capture a thought from the dashboard closes the loop without leaving it.

Fill a gap on request

Every blue “write this next” node is a note that does not exist. A button could draft it from surrounding notes and leave it for the person to correct — a first draft, never a final one.

05 Later — from tool to platform

These change what Nautilus is, and each brings real problems with it.

DirectionWhat it addsWhat it costs
Mobile capture Catch a thought on a phone; the Organise agent files it overnight Sync, and a second codebase
Shared vaults A study group or team building one body of knowledge together Accounts, permissions, conflict resolution — the end of “single user”
An agent SDK Anyone writes their own agent against the same safety contract A stable API, and sandboxing code you did not write
Hosted version Nothing to install; works from any browser Running costs, and it breaks the local-first promise outright
Any domain, not just AI Medicine, law, languages — the roadmap format is generic Curated starter plans per field
The tension worth naming

Every item in this table pulls against the thing that makes Nautilus good. Local-first, no accounts, no database, plain files — those constraints are why it is simple and private. A hosted multi-user version is a different product with different trade-offs, not a bigger version of this one.

The right move is probably to keep the local tool honest and let sharing be an export, not a migration.

06 Who else this serves

The study plan is an example, not the product. The pattern is general.

Students

Any structured syllabus fits the same shape: stages, topics, notes that prove you covered them. Revision becomes automatic because the questions come from what you wrote, and the gaps are visible instead of remembered.

People changing career

The closest fit to what exists. A plan with stages, evidence of progress, a record of applications, and interview practice drawn from your own understanding rather than a generic question bank.

Working professionals

Fast-moving fields make notes go stale. The Conflicts agent already flags where your notes disagree with each other — the same idea extends to flagging where your notes disagree with something newer you saved.

Teams

An onboarding vault that answers “how does deployment work here?” from the team's own documents, and reports which parts are thin, stale or contradictory. That is a real product, and it is the same code.

The generalisation

Nautilus is not a study app. It is a way to keep a body of knowledge honest — answerable, traceable, and maintained by something other than willpower. Studying is just the easiest case to demonstrate.

07 What would have to be fixed first

Known limitations, stated plainly. Listing these is a strength, not an admission.

LimitationWhy it mattersThe fix
Conflict detection is not repeatable The same vault checked twice can give different findings — it is a review aid, not a guarantee Fixed comparison batches and a stable ordering, plus a recorded baseline
Search misses synonyms Different words for the same idea never match Embeddings, measured against the current scoring rather than assumed better
Every request re-reads the vault Correct, and fine for hundreds of notes; not for a hundred thousand Cache on file modification time — still no database
Free tiers run out Batch agents meet rate limits regularly Already mitigated by the fallback chain and a local model; a queue would finish the job
Agents write, but nothing reviews An agent that files a note wrongly is only caught by reading it A review queue: agents propose, the person approves in one click
Single user, no auth Fine locally; unsafe the moment it is shared Accounts — but only if the hosted direction is actually taken
The one to fix first

The review queue. Everything else is performance or polish; this one is about trust. The more agents write to the vault, the more it matters that a person can see what changed and undo it. Growth without it makes the system harder to trust, not more useful.

08 What we would not build

A roadmap is also a list of refusals.

  • LinkedIn scraping. No public API exists for connections or applications, and scraping breaks their terms and gets accounts restricted. The manual tracker gives the same answer without the risk.
  • Fully autonomous editing. Agents propose; a person decides. A system that rewrites your notes unsupervised is one bad inference away from corrupting the thing it exists to protect.
  • Locking notes into a database. The moment the notes are not plain files, “delete Nautilus and lose nothing” stops being true — and that promise is most of why it is worth using.
  • A paid tier that gates the basics. The whole system was built to run free on a normal laptop. Charging for retrieval or the dashboard would contradict the premise.
  • Engagement metrics. Streaks and daily-active-user pressure would make it another app demanding attention. The point is that it maintains itself so you do not have to show up for it.
