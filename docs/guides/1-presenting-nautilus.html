01 Nautilus in one minute

Learn this paragraph. Everything else is detail.

Say this first

“Nautilus turns a folder of plain notes into a system that can show you what you know, answer questions using only your own writing, and keep itself organised. Everything runs on your own machine, the notes stay plain text files, and nothing in it costs money.”

Why it exists

Four things already exist, and each solves only part of the problem:

What existsWhat it can't do
Note apps (Obsidian, Notion)They store your notes but can't think about them
Chatbots (ChatGPT)They can think, but they don't know anything about you
AI note tools (Notion AI)Your data sits on their servers and you rent the AI
Productivity methodsThey only work if you stay disciplined forever
The sentence that wins the argument

“Obsidian stores but can't reason. ChatGPT reasons but doesn't know you. Nautilus does both — over files you own, with an AI you can swap out in one line.”

The theme to repeat

Nothing here costs money and nothing requires installing a big framework. Every choice was made so the whole thing runs on a normal laptop with a free AI key — or with no internet at all, using a local model.

How big is it?

About 4,300 lines — roughly 900 of backend, 1,400 of frontend, 1,200 of agents, 300 of tests, and 500 of supporting code. Small enough that every line was written deliberately.

03 How the whole thing works

Three parts. Learn the shape and you can explain any of it.

The best single point in the project

There is no database. If you copied your notes into a database, you'd have two copies of the truth, and they can disagree — that's where “why hasn't my edit shown up?” bugs come from. Reading the folder every time removes that whole problem. Nothing to sync, because there's nothing else.

04 What happens when you ask a question

The single most likely thing you'll be asked to explain.

Why only five notes?

An AI can only read a limited amount at once, and sending everything would be slow and expensive. So the system picks the five notes most likely to contain the answer. The picking is the clever part — a perfect AI given the wrong notes still gives a wrong answer.

If asked how it avoids making things up

“Four ways. It only sees notes from the vault. It's told to use nothing else. It has to name which notes it used, so you can check. And if no note matches, it never calls the AI at all.”

05 The four screens

What each part of the dashboard is for.

1 · Learning Path — the main view

Six columns, one per month of a study plan. Each holds the topics for that month:

  • Teal with a tick — done. The note exists and has real content.
  • Blue with an arrow — unlocked now. This is what to study next.
  • Grey and dashed — locked. A later stage.
The clever bit — worth saying out loud

Nothing marks a topic as complete. There's no checkbox and no database of progress. A topic counts as done when a note about it exists and has been properly written. So the plan grades itself against the notes — the way to finish a topic is to actually write it up.

2 · Notes and Ask

Every note, newest first, with a filter box. Ask a question and the answer arrives with clickable source chips. Clicking any note opens a full note page with an auto-generated concept map.

3 · Agents

Seven background workers, each with a schedule and a RUN button. RUN is always a preview — it shows what the agent would do and writes nothing. A web page should never be able to edit your notes.

4 · System

Live status: which AI is connected, vault size, link counts, when each agent last ran, uptime. Every row is read from something real — nothing is a placeholder.

06 The seven agents

The part that makes this a system rather than a search box.

AgentWhat it doesSpeed
ProgressGrades the study plan against the notesinstant
ApplicationsCounts job applications, says how many to send todayinstant
OrganiseFiles rough notes into the right folder with tags and links~2 min
DigestWrites a weekly summary of what you studied~1 min
CoachMakes interview questions from your own notes~2 min
RadarReads AI news feeds, keeps only what matches your notes~2 min
ConflictsFinds notes that contradict each other3 min+
For the demo — important

Click Progress and Applications. Both finish instantly because they don't need the AI. The others work, but make everyone wait a couple of minutes — don't click Conflicts in front of an audience.

The four safety rules

These agents are the only part that can change your notes, so:

  1. Preview by default. Nothing is written unless you add --apply.
  2. Never overwrite. A file is never replaced; it gets a new name.
  3. Never invent. If the AI makes up a link to a note that doesn't exist, it's thrown away.
  4. Always logged. Every run is recorded, even previews.

07 The demo — do it in this order

Six minutes. Practise it once before you present.

  1. Start on the Learning Path “This is a six-month study plan. Teal means done, blue means unlocked next, grey is locked. It says 40 of 48 topics, 83%.”
  2. Point at the blue nodes “These two are what I should study next. Nothing marks them — the plan checks itself against the notes I've actually written.”
  3. Click any teal topic The note page opens. Wait ~10s for the concept map. “The AI broke my note into its ideas and drew how they connect.”
  4. Click a blue link inside the note “Notes link to each other, so you can browse straight through.” Then press Back.
  5. Ask the vault a question Try: “What should I focus on in month 4 and why?” Then click a source chip. “Every answer names its sources, so I can check it.”
  6. Ask something NOT in the notes Try: “What did I write about my holiday in Portugal?” It refuses. This is the best moment in the demo — “that's the difference between this and ChatGPT.”
  7. Scroll to Agents, click Progress “Seven background workers. This one grades my plan. RUN is always a preview — a web page can't edit my notes.”
  8. Point at the System panel “Live status. Every row is real — the AI connected, my vault size, when each agent last ran.”
If you only have two minutes

Do steps 1, 5 and 6. The learning path, one grounded answer, and the refusal. That's the whole idea of the project in 90 seconds.

08 Questions you'll get

Click to open. Short answers you can say out loud.

Why didn't you use a database?

Because a database means two copies of the notes, and two copies can disagree. Reading the folder every time means there's nothing to sync. It also means if you delete Nautilus, you still have every note — nothing is locked in.

Why keyword search instead of AI embeddings?

Three reasons: it's enough for a few hundred notes, it's free and instant, and it's explainable — I can show exactly why a note was picked.

The honest limit: if a note says “car” and you ask about “automobile”, it misses. Embeddings fix that, and it's the documented next step — but it adds cost and complexity we didn't need yet.

How is this different from ChatGPT?

ChatGPT doesn't know my notes and can't tell me which of them an answer came from. Nautilus answers only from my own writing and names its sources.

And with a local AI model, nothing leaves the laptop at all.

What happens if the AI service goes down?

The dashboard keeps working completely — the learning path, notes, graph and stats never touch the AI. Only the chat stops.

And there's a fallback chain: if Gemini is busy it automatically tries Groq, then the local model. That actually happened while building — Gemini was overloaded, it switched to Groq, the job finished.

Is this actually multi-agent, or just scripts?

Seven agents share one memory — the notes folder. Each one reads it, does its own job, and writes results back for the others to use.

Concrete proof: the Applications agent writes a summary note, and then you can ask the chat “how many applications am I waiting on?” and it answers from that note. One agent's output becomes another part's input.

Can it connect to LinkedIn?

No, and that's deliberate. LinkedIn has no public API for applications or connections, and scraping it breaks their terms and gets accounts banned.

Instead you log applications as notes, and the agent counts them and tells you how many to send today. Same result, nothing that can break.

How do you know it works?

59 automated tests, running in under a second. They cover reading notes, building the link graph, the search scoring, and the agent safety rules.

You can run them live: python backend/test_nautilus.py. That's a stronger answer than describing it.

What was the hardest problem?

The Conflicts agent was reporting failures as “no conflicts found”. When the AI service hit its rate limit, the code caught the error and printed a clean result — so a check that never ran looked identical to one that found nothing.

The fix was making “couldn't check” a different result from “checked, found nothing”, with a test that keeps them apart. It's a bug about being honest in reporting, which is a good thing to have caught.

09 If something breaks

ProblemWhat to do
Page won't loadThe server isn't running. In a terminal:
python -m uvicorn app:app --app-dir backend
Chat says “every provider failed”No internet, or all keys are out. Say: “the dashboard still works — only the chat needs AI.” Then demo the Learning Path and Progress agent.
Concept map won't generateSame cause. The note itself still displays fine.
An agent times outExpected for the slow ones. Use Progress or Applications instead.
Everything looks brokenRefresh the page. If still broken, restart the server.
If the AI fails mid-demo, say this

“That's the free AI tier being busy — which is exactly why the system has four providers and falls back automatically. Let me show you the parts that don't need it.”

Before you present
  • Start the server 10 minutes early and load the page once
  • Open one note so the concept map is already warm
  • Ask one question to confirm the AI is responding
  • Have the terminal open and ready to run the tests
