## 1. Why do we need positional encodings in a transformer, and what would happen if we omitted them?

**From:** [[Transformers Explained]]

**A strong answer hits:** A strong answer notes that self‑attention has no inherent notion of token order, so positional encodings are added to inject sequence information. It also explains that without them the model cannot distinguish where tokens appear, leading to ambiguous representations.

**The usual trap:** Saying attention itself captures order or that positional encodings are optional.

## 2. What is the main reason we track experiments beyond a simple spreadsheet, and why does the specific tool matter less?

**From:** [[Experiment Tracking]]

**A strong answer hits:** A solid answer emphasizes reproducibility: tracking parameters, metrics, data version, git commit, and artefacts lets you reproduce and defend results. It also notes that the tool is just a means to capture this information, not the core value.

**The usual trap:** Focusing on UI features or preferring a tool without mentioning reproducibility.

## 3. When deploying a model with FastAPI, where should model loading occur and why?

**From:** [[Serving a Model with FastAPI]]

**A strong answer hits:** The correct approach is to load the model once at application startup, not inside each request handler, so the weights are read only once. This avoids the huge latency penalty of re‑reading the model on every call.

**The usual trap:** Suggesting the model be loaded inside the request handler or ignoring performance impact.

## 4. Why is an activation function essential in deep neural networks, and what would happen if we left it out?

**From:** [[Neural Network Basics]]

**A strong answer hits:** An activation introduces non‑linearity, enabling the network to approximate complex functions beyond a simple linear map. Without it, stacked layers collapse mathematically into a single linear layer, so the network learns nothing a line couldn’t represent.

**The usual trap:** Claiming activations only help with vanishing gradients or are optional.

## 5. What habit does the note recommend for writing reusable data‑focused Python, and why is it important for testing and deployment?

**From:** [[Python for Data Work]]

**A strong answer hits:** The note advises writing functions in regular Python modules before using them in notebook cells, keeping code outside notebooks. This matters because notebook‑only code cannot be easily tested, deployed, or reviewed.

**The usual trap:** Saying notebooks are sufficient for production or focusing only on type hints.
